## 工作流（SOP）
1. **需求与调研阶段**：鼠接需求分拣 →（并行）虎采集 + 兔分析 + 龙竞品解构 → 鼠整合
2. **TRIZ创新分析阶段**：蛇用TRIZ方法分析问题 → **先判层级**：简单技术矛盾可直查矛盾矩阵/40原理；系统级或根因问题走 **功能分析 → 因果链 → 基于功效的搜索 → 裁剪 → 物理矛盾分离** → 输出创新方向清单 → 鸡评审创新方向可行性
3. **设计与生图阶段**：蛇基于TRIZ方向做设计 → 羊生图 → 鸡评审 → 猴调优 → 鸡复评 →（按需）龙二调整迭代
4. **情报与素材阶段**（并行）：狗技术情报收集 + 猪风格参考/素材库
5. **工作流优化阶段**（并行）：马工作流/节点优化 + 牛标准规范
6. **进化闭环阶段**（持续）：凤监控质量/技能更新，驱动进化闭环
7. **最终评审**：鸡终审 → 鼠输出最终方案

> 📚 **TRIZ方法论真源**：所有TRIZ分析参考 `assets/domain/TRIZ方法论速查表.md`（40原理/39参数/矛盾矩阵/76标准解/九步框架/功能分析/因果链/裁剪）
> 🔴 **现代TRIZ口径**：矛盾矩阵（39参数+40原理）是**入门级**工具，**不是企业级解题核心**（现代TRIZ / RDMI·孙永伟体系）。系统级问题须先做功能分析与因果链定位根因，勿直接套矩阵堆原理；详见真源开头「现代TRIZ视角」。

## 外部专家路由层（External Expert Routing / R24）
- 生肖团 R17–R23 解决的是「团队内部怎么跑」，但本机遇到的真实问题是：**专家中心已有 34 个专家并列展示，无任何派单与仲裁机制（2026-11-14 复活入档时已达 35 个）**——用户提一个需求得自己判断该开哪个专家，两个专家规则打架时无人裁决。R24 补的就是这层**路由与裁决**。
- 定位：新入库的意图型专家属**意图剧本层**（回答「要什么样的图」），生肖团属**执行治理层**（回答「怎么真出图」）。R24 是两层之间的**接缝**，不是把专家塞进生肖团。
- **派单责任人：鼠**（`rat-product-researcher`）——接需求后必须先过 R24 决策树，再派单，不得直接丢给用户自选。**终裁责任人：鸡**（`rooster-design-reviewer`）——路由表未覆盖或仍不定时，鸡有一票否决权。

### R24.3 冲突裁决表（三处已实锤的互打架条款）

**冲突 1 · 品牌 LOGO 与产品名**
- `cmf-design-assistant`：「LOGO、名称、型号**必须内容完全一致，严禁更改**」
- 重构类（`appearance-redesign-master` 的 DNA 重写 / 原创重构模式）：「品牌名**必须全部改写为虚构新名**」
- **裁决**：说「上架 / 商用 / 电商 / 给客户看」→ 保真实 LOGO（CMF 赢）；说「概念 / 提案 / 避开专利 / 原创」→ 用虚构名（重构方赢）；**不确定时默认虚构名**（保守防侵权）。

**冲突 2 · 输出形态（要不要文字说明）**
- `ai-hits-visual-director`：「严禁输出任何分析文字，只出图」
- `appearance-redesign-master` 等：要求输出「设计说明 + CMF + 风险 + 自检结论」
- **裁决**：**按阶段分层**——过程稿（给用户选方向）出说明 + 评分 + 风险；终稿（用户说「就这个 / 定稿 / 出成品图」）只出图零文字。判据是用户是否给出定稿类关键词。

**冲突 3 · 交互节奏（问不问）**
- `ip-infringement-detective`：「先问清楚，最多 6 问」
- 爆款/视觉生产类：「不反问、不停顿，直接生成」
- **裁决**：**按类别二分**——安全类（侵权 / 专利 / 合规）必须先问清，问不全不许出结论；视觉生产类（出图 / 改款 / 电商）不反问，按默认档位直接出，出完再迭代。同一次请求同时涉及两者时，**先问安全项，再直接出图**。

**兜底总规则**：以上未覆盖的冲突 → 升级 `rat-product-researcher`（鼠）判断，仍不定则 `rooster-design-reviewer`（鸡）终裁。
